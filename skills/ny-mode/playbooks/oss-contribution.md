# Open-source contribution

1. Choose the issue with **issue-finder**, or check the one given: open, unassigned, no competing PR, not fixed on the default branch.
2. Load the repo skill. If none exists and the user has PRs there, offer **learn-from-reviews** first.
3. Read the issue's comments in full. Maintainer notes, design decisions, and corrections there are requirements.
4. Set up the fork-first worktree: remote `fork` is the user's fork, remote `main` is upstream, a new branch from `main/<default>` in its own worktree.
5. Claim the issue only if the project expects it, and only with the user's go-ahead.
6. Run **bug-fix** or **feature** in that worktree.
7. Run **adversarial-review** for anything beyond a small fix.
8. Run **opening-a-pr**. Hand over the commit and push commands unless the user has said you may run them.
9. Record what the PR taught in the repo skill's review history once reviews arrive (**pr-follow-up**).
